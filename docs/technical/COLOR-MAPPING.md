# 氷タイルの色マッピング

隣接する赤爆弾・青爆弾の数から、どの氷タイル画像が選ばれるかの完全な対応表。

- 導出元: `src/components/game/Cell.tsx` の `getIceAsset()`
- この表は実装から機械的に展開したもので、手書きではない。
  **`getIceAsset()` を変更したらこの表も必ず再生成すること。**
- 9x9 盤面では 1 セルの隣接セルは最大 8 なので、有効な組み合わせは `赤 + 青 <= 8` の **45 通り**。

## 現在のロジック

```ts
if (adjacentRed === 0 && adjacentBlue === 0) → ice-clear
else if (adjacentBlue === 0 || adjacentRed >= adjacentBlue * 2) → tone = red
else if (adjacentRed === 0 || adjacentBlue >= adjacentRed * 2) → tone = blue
else → tone = mix

level = clamp(adjacentRed + adjacentBlue, 1, 4)
```

トーンは**比率**（2倍しきい値）で決まり、濃さは**合計数**で決まる。この2つが独立しているのが後述の問題の原因。

**45 通りの状態が 11 種類のタイルにしか分かれていない。**

## 既知の問題

### 1. 未使用アセットが2枚ある

`ice-mix-1` と `ice-mix-3` は **どの組み合わせでも選ばれない**（ファイルは存在するが一度も描画されない）。

- `mix-1` が出るには `level = 1`、つまり `赤 + 青 = 1` が必要だが、
  片方が0なら必ず `red` か `blue` に分類されるため mix にならない。
- `mix-3` が出るには `赤 + 青 = 3` かつ mix 判定が必要だが、
  `赤1青2` と `赤2青1` はどちらも2倍しきい値に引っかかって `blue-3` / `red-3` になる。

結果、mix は実質 `mix-2`（赤1青1のみ）と `mix-4`（残り9通り全部）の **2段階しかない**。

### 2. 高密度で情報が消える

`level` が 4 で頭打ちになるため、**赤4個以上はすべて同じ絵**になる。
`ice-red-4` と `ice-blue-4` がそれぞれ13状態を兼ねており、
爆弾が多い局面（TA hard、Endless 後半）ほど盤面から読み取れる情報が減る。

### 3. 同じ絵に別の意味が重なる

`赤1青3` と `赤0青4`（純青4個）はどちらも `ice-blue-4`。
「赤が混じっているかどうか」という推理に必要な情報が、濃い側で失われる。

### 4. 段差が飛ぶ

`赤1青1` → `mix-2` の次が `赤2青2` → `mix-4` で、`mix-3` を経由しない。
濃さの変化が連続していないため、隣り合うマスの比較がしづらい。

## 再生成の手順

`getIceAsset()` を変更した場合は、実装と同じロジックを移植したスクリプトで
45通りを総当たりして表を作り直す。手で書き換えないこと。
