# D: テスト整備

## 目的

ゲームの中核ロジックに自動テストを入れ、変更で壊れたことを検出できるようにする。

## 背景

**自動テストが1件も存在しない。** CI は `npm run lint` と `npm run build` だけで、
どちらもゲームの挙動が壊れたことを検出できない。

これが現時点で最大の技術的負債。実際、盤面の描画刷新のときに
`cloneBoard` の copy-on-write 化を「テストが無いので危険」という理由で見送っている。
テストが入れば、その手の改善に踏み込めるようになる。

## 同時実行の制約

**レーンE（Next.js 16 移行）と同時に走らせないこと。**
両方 `package.json` を触るため必ず衝突する。

## 触ってよいファイル

- 新規のテストファイル（`src/**/*.test.ts` など）
- `package.json`（テストランナーの追加、`test` スクリプト）
- `package-lock.json`
- `.github/workflows/ci.yml`（テスト実行ステップの追加）
- テストランナーの設定ファイル（新規）

## 触ってはいけないファイル

- **テスト対象の実装コード。** テストを通すために実装を書き換えない。
  もし実装のバグを見つけたら、**直さずに報告する**。修正は別タスクにする
- `src/components/game/` 配下 — レーンAの担当
- `src/app/api/` 配下 — レーンCの担当
- `docs/PROJECT-STATUS.md`, `docs/ROADMAP.md` — 全レーン共通で編集禁止

## やること

まず**最小限**から始める。網羅率を上げるより、中核が守られていることが大事。

### 優先度1: `src/lib/game-logic.ts`

- `generateBoard` — 指定した数の爆弾が置かれる／隣接数が正しく計算される
- `revealCell` — 爆弾を踏んだとき／安全なセル／隣接0での連鎖開放／既に開いたセル
- `checkWin` — 非爆弾セルが全部開いたときだけ true。旗は勝利条件に関係しない
- `toggleFlag` — hidden と flagged の往復。開いたセルには効かない

**連鎖開放（BFS）のテストは特に厚くすること。** ここが一番壊れやすく、
一番壊れたときに気づきにくい。

### 優先度2: `src/lib/ice-colors.ts`

- 45状態すべてがユニークな色になる
- 同じ合計数の色は明度と彩度が一致する（この性質が崩れると設計が壊れる）

### 優先度3: `src/hooks/useGame.ts` の reducer

- スコア計算、スピードボーナス、被弾時のライフ減少、レベルクリアのボーナス

## テストランナーの選定

Next.js 15 / React 19 / TypeScript で動くものを選ぶ。
**現時点では純粋な関数のテストだけで足りる**ので、
コンポーネントの描画テストまで用意する必要はない。軽いものを選ぶこと。

## 完了条件

- `npm test` で実行できる
- CI（`.github/workflows/ci.yml`）でテストが走り、失敗するとPRが赤くなる
- 優先度1がすべてカバーされている
- **わざと実装を壊すとテストが落ちることを確認済み**（テストが機能していることの確認）

## 検証

1. `npm run lint` と `npm run build` と `npm test` が通る
2. `revealCell` の連鎖開放の条件をわざと反転させ、テストが落ちることを確認する。
   落ちなければそのテストは意味がない
3. CI 上でもテストが実行されていることを、PRのチェック結果で確認する
