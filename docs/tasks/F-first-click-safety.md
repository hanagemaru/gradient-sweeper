# F: 初手保証

## 目的

最初にタップしたマスで必ず安全に、かつ**広い範囲が連鎖して開く**ようにする。

## 背景

`generateBoard` は入力前に盤面を確定するため、**現状は最初のタップで爆発しうる**。
運だけでゲームが終わるので、体験として明確に良くない。

一般的なマインスイーパーと同じく、初手は必ず広く開く挙動にする。

## 前提となる知識

初手の時点で**プレイヤーはまだ何の情報も見ていない**。
そのため盤面を作り直しても、プレイヤーから見て矛盾は起きない。ここが実装を簡単にしている。

現在の `generateBoard`（`src/lib/game-logic.ts`）は
81マスをシャッフルして先頭 N 個を爆弾にしている。

```ts
const positions = shuffleArray(
  Array.from({ length: GRID_SIZE * GRID_SIZE }, (_, i) => i)
);
```

## やること

### 1. `generateBoard` に除外リストを渡せるようにする

爆弾を置ける候補から、指定されたマスを取り除くだけ。

```ts
const positions = shuffleArray(
  Array.from({ length: GRID_SIZE * GRID_SIZE }, (_, i) => i)
    .filter((i) => !excluded.has(i))
);
```

**ループで引き直す実装にしないこと。** 候補から除くほうが単純で、統計的な偏りも出ない。

### 2. 初手で盤面を作り直す

`REVEAL_CELL` の処理で、その盤面の初手なら、
**タップしたマスとその周囲8マスを除外して**盤面を作り直してから開く。

3x3を除外すれば初手の隣接数が必ず0になり、連鎖して広く開く。

### 3. 高密度でのフォールバック

`MAX_BOMBS = 80` なので、9マス除外すると72マスに80個は入らない。

**爆弾が `81 - 9 = 72` 個を超える場合は、タップしたマス1つだけの除外に落とす。**
ここが実装上いちばん間違えやすい箇所。境界値のテストを必ず書くこと。

### 4. 「今が初手か」の判定

**状態を持たせず、盤面から導出すること。**
開いたセル（`revealed` または `exploded`）が1つも無ければ初手とみなす。

`useGame` に `isFirstClick` のようなフラグを足すと、
`NEXT_LEVEL` や `RESET` でのリセット漏れがバグになる。
盤面から導けば、新しい盤面を作った時点で自動的にリセットされる。

旗は初手の判定に影響しない（先に旗を立ててから開くプレイがありうる）。

### 5. Endless の各レベルに適用する

初手保証は「ゲームごと」ではなく**「盤面ごと」**。
レベルが変わって新しい盤面になったら、その盤面の初手も保証される。
4の方式で導出していれば自動的にそうなる。

## テスト

**このタスクは自前でテストを書くこと。** 触るのが最も重要なロジックのため。

vitest は導入済みで `npm test` で走る。`src/lib/game-logic.test.ts` に既存のテストがあるので、
そこに足すか別ファイルを作る。**`package.json` は触らないこと。**
レーンD（テスト整備）の完了は待たなくてよい。

最低限これらを確認する。

- 除外したマスに爆弾が置かれない
- 3x3 を除外したとき、中心の隣接数が0になる
- 初手をタップすると必ず連鎖が起きる（開いたセルが1マスで終わらない）
- **爆弾72個超のとき**、フォールバックが働き、
  タップしたマスだけは安全で、盤面の生成が失敗しない
- 爆弾80個（`MAX_BOMBS`）でも破綻しない
- 初手以降は保証が働かない（2手目以降は普通に爆発しうる）
- レベルが上がって新しい盤面になったら、その盤面でも初手が保証される

## 完了条件

- 初手で爆発しない
- 初手で必ず複数マスが連鎖して開く（爆弾72個以下の場合）
- 高密度でも生成が破綻しない
- 上記のテストが通る
- `npm run lint` と `npm run build` が通る

## 検証

1. `npm run lint`, `npm run build`, テストが通る
2. Netlify のデプロイプレビューで Endless を何度も開始し、
   **初手が毎回広く開くこと**を確認する（10回以上試すこと。運で通ることがある）
3. Time Attack の hard（爆弾30個）でも同様に確認する
4. Endless を進めて爆弾が増えた状態でも破綻しないことを確認する
