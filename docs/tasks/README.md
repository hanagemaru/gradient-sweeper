# タスク仕様

複数のセッションを同時に走らせるための仕様書置き場。

## 使い方

新しいセッションを始めるとき、次の一行だけを入力する。

```
docs/tasks/A-particles.md を読んで実装して
```

仕様書に目的・触ってよいファイル・完了条件が書いてあるので、
毎回長い指示を打ち込む必要がない。スマホから始めるときはこれが効く。

## 並行の原則

**タスクは機能ではなくファイルで分ける。**
コンフリクトはファイルの重なりからしか生まれない。
スマホではコンフリクト解消が特につらいので、そもそも起きない分け方にする。

| レーン | 内容 | 同時実行 |
|---|---|---|
| [A](./A-particles.md) | マスを開けたときの飛散演出 | 可 |
| [B](./B-pixel-ui.md) | ゲーム画面以外のピクセル化 | 可 |
| [C](./C-score-validation.md) | スコアのサーバー側検証 | 可 |
| [D](./D-tests.md) | テスト整備 | 可 |
| [E](./E-nextjs16.md) | Next.js 16 移行 | **単独で実施** |
| [F](./F-first-click-safety.md) | 初手保証 | 可 |
| [G](./G-fixed-canvas-letterbox.md) | 固定キャンバス＋レターボックス | **レーンB（PR #10）に取り込み済み** |
| [H](./H-result-overlay.md) | リザルト画面をゲーム画面の上にオーバーレイ | **単独で実施**（`/game` と `/result` の両方に関わるため） |
| [I](./I-canvas-fit.md) | 固定キャンバスの基準高さを実機ビューポートに合わせる | 可（レーンH とはファイルが重ならない） |
| [J](./J-ranking-panel.md) | ランキングをパネルのオーバーレイ表示にする | **単独で実施**（レーンH のマージ後。`PixelScene` とゲーム画面の両方に関わるため） |

A・B・C・D・F は触るファイルが1つも重ならないので、同時に走らせてよい。

G はレーンBとファイルがほぼ完全に重なる。当初は PR #10 のマージ後に単独で行う
予定だったが、結局 PR #10 の中で実施した。仕様は G の資料として残してある。

E は `package-lock.json` が巨大なコンフリクトになるため、他を全部マージしてから単独で行う。

**必要な依存はすでに入っている**（vitest、DotGothic16）。
E 以外のレーンは `package.json` を触らずに済むはずなので、D も含めて並行できる。
依存の追加が必要だと判断した場合は、勝手に入れずに報告すること。

## 全セッション共通のルール

1. **1タスク＝1ブランチ＝1PR。** 同じブランチに2セッションを当てない
2. **仕様書の「触ってはいけないファイル」を必ず守る。**
   自分のレーンの外に手を伸ばした瞬間、他のセッションと衝突する
3. **`docs/PROJECT-STATUS.md` と `docs/ROADMAP.md` は編集しない。**
   全セッションが更新すると必ずコンフリクトする。
   共有すべき内容があれば、PR説明か自分のタスク仕様に書く。
   これらの集約は全部マージし終えてから、単独のセッションで行う
4. **依存は勝手に追加しない。** `package-lock.json` は手で直せないので、
   必要になったら実装せずに報告すること
5. **緑になったらすぐマージ。** ブランチを長生きさせるほどコンフリクト率が上がる
6. 検証は `npm run lint` と `npm run build`。両方通ってから PR を出す
7. 見た目に関わる変更は Netlify のデプロイプレビューで確認する

## 仕様書の書き方

新しいタスクを足すときは既存のものに倣う。最低限これだけは書く。

- **目的** — 何のためか。判断に迷ったときの拠り所になる
- **背景** — なぜ今それをやるのか。調査済みの事実があれば書く
- **触ってよいファイル / 触ってはいけないファイル** — レーンの境界
- **やること** — 手順ではなく、達成すべき状態
- **完了条件** — 何をもって終わりとするか
- **検証** — どう確かめるか
